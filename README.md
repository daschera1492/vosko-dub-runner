# vosko-dub-runner

رانر گیت‌هاب برای دوبلهٔ خودکار ویدیو با [vosko.ai](https://vosko.ai)؛ بدون مرورگر، فقط API.

ورودی: **یک لینک مستقیم ویدیو/صدا** + **زبان مبدأ** + **زبان مقصد**.
خروجی پیش‌فرض: **یک فایل MP3 واحد** که از چسباندن تکه‌های دوبله ساخته می‌شود و به‌صورت asset در **Releases همین مخزن** منتشر می‌شود.
اگر `output_mode=video` انتخاب شود، همان صدا روی ویدیوی اصلی سوار می‌شود.

## چطور کار می‌کند

1. **زبان‌ها زنده خوانده می‌شوند** — `scripts/languages.mjs` صفحهٔ ساخت پروژهٔ vosko.ai را می‌خواند،
   دو آرایهٔ زبان را از باندل Nuxt بیرون می‌کشد (لیست مبدأ شامل `Auto Detect` و لیست مقصد)
   و `data/languages.json` و منوی کشویی `.github/workflows/dub.yml` را می‌سازد.
   گردش‌کار `Sync languages` روزانه این کار را می‌کند؛ هنگام هر دوبله هم لیست دوباره گرفته و
   انتخاب کاربر با آن تطبیق داده می‌شود.
2. **تقسیم هوشمند** — اگر فایل بلندتر از سقف ۵۸ ثانیه باشد، Whisper کلمه‌به‌کلمه زمان‌بندی می‌دهد،
   برش‌ها وسط سکوت (فاصلهٔ ≥ ۳۰۰ms) و هرگز وسط جمله زده می‌شود، و هیچ تکه‌ای از ۵۸ ثانیه
   (سقف سایت: ۶۰ ثانیه) بیشتر نمی‌شود. اگر Whisper نبود، `silencedetect` جای آن را می‌گیرد.
   دنبالهٔ کمتر از ۳ ثانیه به تکهٔ قبل چسبانده می‌شود.
3. **اکانت‌ها بازاستفاده می‌شوند** — رانر برای هر اکانت یک ایمیل تازه می‌گیرد، کد ورود را از
   همان صندوق می‌خواند، لاگین می‌کند و هدیهٔ ثبت‌نام را می‌گیرد. دو منبع ایمیل دارد:
   `dub.yml` از پلاگین `vosko-dub-bridge` روی وردپرس (`sara-ahmadi@masezahedi.com`) و
   `dub-emailnator.yml` از [emailnator.com](https://www.emailnator.com) که یک آدرس واقعی جیمیل
   با الیاس نقطه‌ای (`name.with.dots@gmail.com`) می‌سازد؛ در دومی هیچ سرور/ایمیلی از ما دخالت ندارد.
   هر اکانت تا وقتی کردیتش از
   `ACCOUNT_MIN_CREDITS` بیشتر است چند تکه را دوبله می‌کند و بعد بازنشسته می‌شود؛ این کار تعداد
   ورودها (و در نتیجه سقف «تعداد کد ورود از یک IP» سایت) را چند برابر کم می‌کند.
   اگر سایت `HTTP 429` بدهد، رانر اکانت را عوض نمی‌کند، بلکه با انتظار پله‌ای (۱ تا ۱۵ دقیقه) همان
   درخواست را تکرار می‌کند.
4. **دوبله و دانلود** — تکه آپلود می‌شود، ترجمه/دوبله شروع می‌شود و تا آماده‌شدن پول می‌شود.
   سپس صدا طوری گرفته می‌شود که **موسیقی و افکت‌های پس‌زمینهٔ اصلی حفظ شوند**:
   اول فایل نهایی خود سایت (`export_vocal_with_bgm_url`، همان «Translated audio (.MP3)»)،
   بعد در صورت نبود آن، میکس محلی سگمنت‌های TTS روی `original_bgm_url` (صدای اصلی بدون گوینده).
   فقط اگر هیچ‌کدام موجود نبود، به `editable_chunk_info.chunks[].translated_audio_url` (صدای تنها) برمی‌گردد.
5. **مونتاژ و انتشار** — هر تکهٔ دوبله به طول دقیق بازهٔ خودش «پد» می‌شود تا صدا با تایم‌لاین ویدیو هم‌تراز بماند،
   سپس تکه‌های MP3 با ffmpeg به هم می‌چسبند و فایل نهایی با `gh release create`
   در Releases همین مخزن منتشر می‌شود. پیش‌فرض **فقط صدا** است؛ اگر `output_mode=video` باشد،
   صدا روی ویدیوی اصلی (بدون رمزگذاری مجدد تصویر) سوار می‌شود.
6. **قابل ادامه** — `state.json` در پوشهٔ کار، تکه‌های تمام‌شده را نگه می‌دارد؛ اجرای دوباره
   آن‌ها را دوباره دوبله نمی‌کند. نسخهٔ میکس (`mixVersion`) هم ذخیره می‌شود؛ خروجی‌های قدیمی که
   پس‌زمینه ندارند دوباره ساخته می‌شوند. `state.json` و تکه‌ها در آرتیفکت `dub-output` هم بالا
   می‌روند، پس با دادن `resume_run_id` یک اجرای نیمه‌کاره از همان‌جا ادامه می‌یابد.

## دو رانر (یکی هسته، دو منبع ایمیل)

هر دو ورک‌فلو یک کد را اجرا می‌کنند (`scripts/run.mjs`) و فقط منبع اکانت/کد فرق می‌کند:

| ورک‌فلو | منبع ایمیل و کد | سکرت‌های لازم | پیش‌فرض هم‌زمانی |
|---|---|---|---|
| `dub.yml` (قدیمی) | پلاگین `vosko-dub-bridge` روی وردپرس خودمان | `VDB_BASE_URL`, `VDB_KEY` | ۱ |
| `dub-emailnator.yml` (جدید) | [emailnator.com](https://www.emailnator.com) — جیمیل واقعی با الیاس `.Gmail` | هیچ (فقط پروکسی) | ۵ |

در رانر جدید:

- برای هر تکه یک آدرس تازه با `POST /api/generate-email` و بدنهٔ `{"ids":[3]}` گرفته می‌شود؛
  `3` همان تیک **`.Gmail`** است (`1`=Domain، `2`=+Gmail، `8`=GoogleMail). یعنی آدرس همیشه
  `name.with.dots@gmail.com` است و بقیهٔ تیک‌ها خاموش می‌مانند.
- هر ۴ ثانیه `POST /api/message-list` صندوق را می‌خواند، پیام‌های قفل‌شده (قدیمی‌تر از ۲۴ ساعت)
  و پیام‌های قدیمی‌تر از سه دقیقه را نادیده می‌گیرد تا کدِ یک الیاس دیگرِ همان صندوق اشتباهی
  برداشته نشود، و کد را از subject یا بدنهٔ پیام (`GET /api/message/<id>`) درمی‌آورد.
  تست واقعی: کد ۶ ثانیه بعد از درخواست رسید و لاگین + هدیهٔ ثبت‌نام انجام شد.
- پروکسی، برش، Whisper، مونتاژ و انتشار دقیقاً همان `dub.yml` است؛ هیچ تغییری نکرده.
- هشدار: صندوق emailnator **عمومی** است؛ فقط برای کد یک‌بارمصرف ورود مناسب است، نه ایمیل خصوصی.
- `VDB_*` و پلاگین وردپرس در این مسیر استفاده نمی‌شوند؛ اگر دیگر لازم نیستند، `dub.yml` و
  سکرت‌های `VDB_*` را می‌توان حذف کرد.

عیب‌یابی سریع بدون دوبله (یک آدرس می‌سازد و منتظر کد می‌ماند):

```bash
node scripts/emailnator-check.mjs 120
```

## اجرا (GitHub Actions)

`Actions → Vosko dub → Run workflow`:

| ورودی | توضیح |
|---|---|
| `video_url` | لینک مستقیم فایل (mp4/mkv/mov/wav/mp3/…) |
| `source_lang` | از لیست زندهٔ سایت (پیش‌فرض `Auto Detect`) |
| `target_lang` | از لیست زندهٔ سایت (مثلاً `Persian (Farsi)`) |
| `chunk_seconds` | طول نرم هر تکه: در `dub.yml` گزینه‌های ۳۰/۴۰/۵۲ (سقف واقعی ۵۸)، در `dub-emailnator.yml` گزینه‌های ۲۰/۳۰/۴۰ و پیش‌فرض ۳۰ (سقف سخت ۳۸ ثانیه به‌خاطر هدیهٔ ۵۰ کردیتی) |
| `pipeline_type` | `auto` = دقیقاً انتخاب سایت (فارسی → `standard`، زبان‌های Core → `ultra`)؛ برای عیب‌یابی می‌توان `standard`/`ultra` را اجبار کرد |
| `no_chunk` | `true` = کل فایل بدون برش ffmpeg در یک پروژه آپلود شود (تست/تشخیص) |
| `max_chunks` | تست سریع: فقط N تکهٔ اول دوبله شود (`0` = همه) |
| `debug_dump` | `true` = JSON خام آیتم (سگمنت‌ها و URL صداها) کنار خروجی ذخیره شود |
| `whisper_model` | `tiny` / `base` / `small` برای زمان‌بندی کلمات |
| `output_mode` | `audio` = یک MP3 واحد (پیش‌فرض) / `video` = صدا روی ویدیوی اصلی |
| `audio_source` | `auto` (پیش‌فرض) / `export` = اول فایل نهایی سایت / `mix` = میکس سگمنت‌ها روی پس‌زمینه / `voice` = فقط صدا |
| `parallel_chunks` | چند تکه هم‌زمان دوبله شود: `1` امن‌ترین (پیش‌فرض) تا `5` سریع‌ترین |
| `proxy_enabled` | `true` = هر اکانت از یک IP مسکونی جدا (Oxylabs) بیرون می‌رود؛ `false` = IP خودِ رانر |
| `proxy_country` | کشور خروج پروکسی؛ `auto` یعنی بین `us,de,nl,gb` بچرخد (هر اکانت یک کشور) |
| `resume_run_id` | شمارهٔ Run قبلی که `state.json` و تکه‌هایش ادامه داده شود (خالی = از صفر) |
| `queue_group` | اختیاری؛ اجراهایی که مقدار یکسان دارند پشت هم می‌مانند. خالی = اجراها **هم‌زمان** اجرا می‌شوند |
| `publish_release` | انتشار خروجی به‌صورت Release (پیش‌فرض بله) |

### انتخاب پایپ‌لاین (مهم)

سایت برای هر زبان مقصد یک `pipeline_type` انتخاب می‌کند: `ultra` فقط برای ۱۹ زبان
Core (انگلیسی، چینی، ژاپنی، کره‌ای، اسپانیایی، آلمانی، فرانسوی، پرتغالی، تایلندی،
اندونزیایی، ویتنامی، مالایی، فیلیپینی، ایتالیایی، روسی، هلندی، لهستانی، ترکی، سوئدی)
و `standard` برای بقیه، از جمله **فارسی**. رانر هم دقیقاً همین قاعده را پیاده می‌کند؛
اجبار `ultra` روی زبانی که Core نیست باعث خروجی بی‌معنی می‌شود.

### Secretها

| نام | مقدار |
|---|---|
| `VDB_BASE_URL` | `https://aiwithmase.ir/wp-json/vosko-dub/v1` |
| `VDB_KEY` | کلید سرویس رانر از صفحهٔ «Vosko Dub» وردپرس (`vdb_…`) |
| `PROXY_OXYLABS` | پروکسی مسکونی Oxylabs به شکل `pr.oxylabs.io:7777:customer-resi_<ID>:<PASSWORD>` (رمز را با `+` و بدون URL-encode بنویسید) |
| `GH_PAT` | فقط برای گردش‌کار `Sync languages` لازم است: توکن با scope `workflow` (چون `GITHUB_TOKEN` اجازهٔ تغییر فایل‌های `.github/workflows` را ندارد) |

`GH_TOKEN` برای انتشار Release از `${{ github.token }}` استفاده می‌کند و `permissions: contents: write` دارد.

### پروکسی (Oxylabs)

- **هر اکانت یک IP جدا**: نام کاربری با پارامترهای خود Oxylabs ساخته می‌شود،
  `customer-resi_<ID>-cc-<country>-sessid-<random>-sesstime-30`؛ یعنی هر اکانت یک سشن چسبندهٔ
  نیم‌ساعته دارد و دو اکانت هم‌زمان هرگز یک IP نمی‌گیرند. چون یک اکانت چند تکه را دوبله می‌کند،
  IP آن هم بین تکه‌ها ثابت می‌ماند.
- **فقط درخواست‌های API از پروکسی رد می‌شوند.** آپلود به OSS (`ossPut`)، دانلود MP3/ویدیو،
  دانلود فایل ورودی و تماس‌های bridge همه مستقیم و با IP رانر انجام می‌شوند؛ بنابراین پهنای باند
  گران مسکونی صرف چند صد کیلوبایت JSON می‌شود، نه ۲۰ تا ۶۰ مگابایت مدیای هر تکه.
- مکانیزم: `scripts/lib/proxy.mjs` سشن را می‌سازد و `scripts/lib/http.mjs` فقط داخل
  `withProxy(...)` تونل `CONNECT` می‌زند. هیچ‌جا `fetch` سراسری دست‌کاری نمی‌شود، پس آپلود/دانلود
  ناخواسته پروکسی نمی‌شود.
- اگر `proxy_enabled=true` باشد ولی Secret خالی باشد، اجرا همان اول با پیام روشن متوقف می‌شود
  (نه اینکه بی‌صدا با IP رانر برود).

### ورود و اثر انگشت دستگاه (X-Device-Fingerprint)

از ۲۰۲۶-۱۱ سایت ورودی‌های احراز هویت (`/user/email/code` و `/user/login/email`) را پشت
اثر انگشت دستگاه (شناسهٔ FingerprintJS) گذاشته است. اگر هدر `X-Device-Fingerprint` نباشد،
پاسخ `HTTP 400` با `{"code":10001,"msg":"invalid parameters"}` است — دقیقاً همان خطایی که
اجرای ۴۲۸۳۲۷۴۳۹۵۶ را متوقف کرد. کد `20031` هم یعنی «این شناسه پذیرفته نشد، یکی تازه بفرست».

رانر برای هر اکانت یک شناسهٔ تصادفی ۳۲ کاراکتری می‌سازد (`scripts/run.mjs` → `newFingerprint`)
و همان را برای درخواست کد و لاگین همان اکانت می‌فرستد؛ یعنی هر اکانت = یک IP پروکسی + یک
اثر انگشت، مثل یک بازدیدکنندهٔ واقعی. اگر سایت `20031`/`10001` برگرداند، یک‌بار با شناسهٔ
تازه دوباره تلاش می‌شود. کدهای خطای خود API (۲۰۰۱۹/۲۰۰۲۰/۲۰۰۳۰/۲۰۰۳۱/۱۰۰۰۱) حالا روی
`HttpError.code` هم ست می‌شوند تا منطق retry/ throttle فقط به متن پیام وابسته نباشد.

### اجرای هم‌زمان

هر اجرا اکانت‌ها، پوشهٔ کار و تگ Release مستقل دارد، پس به‌طور پیش‌فرض چند اجرا **موازی** اجرا می‌شوند
(گروه concurrency هر اجرا یکتاست). برای محدودکردن عمدی، به چند اجرا یک `queue_group` یکسان بدهید.
توصیه: به‌خاطر محدودیت نرخ سایت و ورودهای هم‌زمان، هم‌زمان بیشتر از ۲–۳ اجرا نزنید.

## اجرای محلی

```bash
export VDB_KEY=vdb_…
export VDB_BASE_URL=https://aiwithmase.ir/wp-json/vosko-dub/v1
export INPUT_URL=https://example.com/clip.mp4
export SOURCE_LANG="Auto Detect"
export TARGET_LANG="Persian (Farsi)"
export PUBLISH_RELEASE=false
node scripts/run.mjs
```

پیش‌نیاز: Node 22، `ffmpeg`/`ffprobe`، و برای فایل‌های بلندتر از ۵۸ ثانیه `openai-whisper` در پایتون.

## موسیقی و صدای پس‌زمینه

خروجی دوبله باید علاوه بر گفتار، موسیقی و افکت‌های اصلی را هم داشته باشد. رانر برای هر تکه
به این ترتیب عمل می‌کند:

1. اگر آیتم از قبل خروجی کامل سایت را داشته باشد (`export_vocal_with_bgm_url`)، همان دانلود می‌شود.
2. با `audio_source=export` (یا وقتی سگمنتی برای میکس نیست) یک export واقعی از سایت درخواست می‌شود
   (`batch-export` + poll روی `items/export/result`). اگر اکانت رایگان اجازه ندهد، بی‌صدا رد می‌شود.
3. در حالت عادی، صداهای TTS هر زیرنویس روی `original_bgm_url` (صدای اصلی بعد از حذف گوینده)
   میکس می‌شوند؛ دقیقاً همان کاری که ادیتور سایت هنگام پخش می‌کند. این مسیر به عضویت پولی نیاز ندارد.
4. اگر آیتم به‌جای سگمنت، یک فایل صدای واحد داشته باشد (پایپ‌لاین `ultra`)، همان فایل هم
   روی `original_bgm_url` میکس می‌شود؛ پس خروجی آن مسیر هم موسیقی دارد.
5. فقط اگر هیچ پس‌زمینه‌ای موجود نبود، به صدای تنها برمی‌گردد و در لاگ/خلاصهٔ اجرا هشدار می‌دهد.

> نکته: خروجی export سایت (`export_vocal_with_bgm_url`) همان «تک فایل MP3 نهایی» با موسیقی است،
> ولی فقط برای اعضای پولی ساخته می‌شود؛ اکانت‌های هدیه (۵۰ کردیت) با
> `10010 membership required` رد می‌شوند. به همین دلیل مسیر اصلی، میکس محلی است که دقیقاً
> همان کاری را می‌کند که پخش‌کنندهٔ خود سایت هنگام پیش‌نمایش انجام می‌دهد.

میزان صدای پس‌زمینه با `BGM_GAIN` قابل تنظیم است (`1` = سطح اصلی، پیش‌فرض).

## سوارکردن دوبله روی ویدیو (mux)

اگر فایل دوبلهٔ نهایی را جدا گرفته‌اید و می‌خواهید صدای اصلی ویدیو **کاملاً حذف** شود و
فقط دوبله با زمان‌بندی خودش پخش شود:

```bash
node scripts/mux.mjs input.mp4 dubbed-fa.mp3 final-fa.mp4
# یا: npm run mux -- input.mp4 dubbed-fa.mp3 final-fa.mp4
```

- تصویر فقط **stream-copy** می‌شود؛ هیچ افت کیفیت یا رندر مجددی ندارد.
- صدا با `-map 0:v:0 -map 1:a:0` جایگزین می‌شود (صدای اصلی حذف، نه میکس).
- دوبله از ثانیهٔ صفرِ خودش شروع می‌شود؛ `apad`+`-shortest` جلوی بریده‌شدن انتهای تصویر را می‌گیرد.
- خروجی AAC 192k استریو 48kHz با `+faststart` برای پخش وب.

## کردیت و خط‌مشی

هدیهٔ ثبت‌نام هر اکانت تازه **۵۰ کردیت** است و هزینهٔ دوبلهٔ `standard` حدود
**۱.۱۶ کردیت به ازای هر ثانیه** (≈۷۰ در دقیقه) — اندازه‌گیری واقعی: تکهٔ ۵۰.۱۲ ثانیه‌ای
دقیقاً ۵۸ کردیت خواست و با `402 insufficient credits` رد شد.
یعنی هر اکانت تنها حدود **۴۰ ثانیه** دوبله را می‌پردازد.
به همین دلیل:
- رانر `dub.yml` (قدیمی، با هدیهٔ بالاتر) تکه‌ها را ≤۵۸ ثانیه می‌شکند.
- رانر `dub-emailnator.yml` سقف سخت را روی **۳۸ ثانیه** می‌گذارد و پیش‌فرض `chunk_seconds=30` است؛
  هر تکه اکانت تازه می‌گیرد.
برای تست‌های ارزان از `max_chunks=1` استفاده کنید.

اگر ساخت اکانت/دریافت کد یک تکه شکست بخورد، رانر تا `max_account_tries` (پیش‌فرض ۴) اکانت تازه
و چند ثانیه فاصله امتحان می‌کند. اگر باز هم نشد، اجرا **fail** می‌شود و خروجی منتشر نمی‌کند؛
چون سکوت گذاشتن جای تکهٔ ناموفق، ویدیویی می‌سازد که سالم به‌نظر می‌رسد ولی چند دقیقه صدا ندارد.
برای رفتار قدیمی (پرکردن با سکوت) `allow_partial=true` بدهید.

## ساختار

```
scripts/run.mjs            ارکستراتور
scripts/languages.mjs      استخراج زندهٔ لیست زبان‌ها + رندر ورک‌فلو
scripts/lib/emailnator.mjs منبع ایمیل/OTP از emailnator (رانر جدید)
scripts/emailnator-check.mjs  تست دستی: یک آدرس بگیر و منتظر کد بمان
scripts/lib/bridge.mjs     کلاینت REST پلاگین (run/identity/OTP) — فقط رانر قدیمی
scripts/lib/vosko.mjs      کلاینت API وُسکو (لاگین، کردیت، آپلود OSS، ترجمه، دانلود)
scripts/lib/media.mjs      برش/چسباندن/ریمکس با ffmpeg
scripts/mux.mjs            جایگزینی صدای ویدیو با فایل دوبله (حذف صدای اصلی)
scripts/lib/whisper_words.py  زمان‌بندی کلمه‌ها با Whisper
ci/dub.template.yml        قالب ورک‌فلوی دوبله (منوها با __…__ جایگزین می‌شوند)
```

## پلاگین وردپرس (فقط رانر قدیمی)

این بخش فقط برای `dub.yml` است؛ `dub-emailnator.yml` به هیچ سروری از ما وابسته نیست.
رانر قدیمی به پلاگین [`vosko-dub-bridge`](../vosko-dub-bridge) وابسته است. پلاگین باید فعال باشد،
کلید `dhk_…` با مجوز `worker` برای DuckMail Hub داشته باشد و یک کلید سرویس `vdb_…` برای رانر صادر کرده باشد.
سلامت: `GET https://aiwithmase.ir/wp-json/vosko-dub/v1/health` → `{"ok":true,...}`.
